# Wagent Ai design system

Preserve the original raster W logo and favicon, near-black violet surfaces, violet primary actions, readable light text and restrained green state accents. Use Segoe UI/system sans, tabular numbers, one-pixel borders and 7–12px corners. Reserve red for failures. No glass, gradient text, fake charts or casino styling. Respect reduced motion.

The current release uses Robinhood Chain mainnet (4663), native ETH gas and EVM 0x token addresses. MetaMask and Phantom must expose the same original EVM owner account and support the chain. Only offer MetaMask and Phantom. Reject unsupported providers and never silently select a different installed wallet. Keep the network and complete address visible because tickers are not unique.

Keep the permanent sidebar with an accessible mobile menu. Use inline numbered setup sections, clear status notices and forms beside review panels; collapse to one column on small screens. Dense tables scroll inside their region. Display missing data as unavailable, cached data with its timestamp and partial portfolios explicitly. Discovery uses aligned search, liquidity and refresh controls, a compact pool-age filter, sorting, result counts and pagination. Tables retain full copyable token addresses and scroll inside their region on mobile. Show partial coverage, data time and useful empty states. Discovery is an indexed feed and not a safety endorsement or complete launch feed.

Owner setup explains encrypted server custody and application-enforced limits before creating a distinct trading wallet. Add ETH reviews an explicit owner-to-trading-wallet transfer on Robinhood Chain, including amount, recipient, gas and expiry. A prominent Add ETH action on Portfolio reuses the existing wallet without repeating setup. Funding does not approve trading. Exchange deposit instructions must warn that other networks and old SOL balances are separate.

Treat returning devices as an existing workspace. Show owner verification as success, explain that the owner signs permissions and receives withdrawals, and identify the separate wallet holding trading funds. A funded-wallet notice links directly to permissions and makes further deposits optional. Saved WhatsApp connections provide Continue with saved connection; different-key replacement is a separate disclosure. Never replay the pairing-success preview when restoring an existing pair. Explain wallet pending requests separately from on-chain transactions and offer a read-only balance check. Unknown deposit outcomes block another in-tab review until the user acknowledges checking wallet Activity.

Trading permission offers Any supported Robinhood token or Only selected token addresses. Scope, operation total budget, UTC daily budget, gas cap, slippage, expiry and revoke stay visible. Changing fields clears the pending review and consent. Display the exact signed message. Replacing permission does not reset daily usage. New grants require fresh owner consent; old Solana signatures grant no EVM authority.

Connections and WhatsApp trading expose clear Agent 1 / Agent 2 selectors with independent pairing and permission state. The single wallet balance and combined budgets stay visible in the summary. Label individual and combined limits explicitly, with a notice that signing updates the shared ceiling for both connections. Show usage for the selected agent and the whole wallet. Keep Agent 2 withdrawal setup collapsed and labelled off until an explicit separate approval. Offer Revoke this agent’s access beside its controls and Revoke all access in the shared summary. Activity includes the source connection label.

WhatsApp withdrawal permission is independent, native ETH only and fixed to the original owner. Explain the unique two-minute confirmation code before signing. Keep separate revoke controls. Website ETH/ERC-20 recovery requires a fresh exact owner signature and revokes advance access. An ambiguous send always leads to a read-only status check, never a retry action. Activity labels distinguish token approval, quote preview, pending confirmation, confirmed and failed. Never display an old receipt as a new trade.

Portfolio separates trading and owner balances, shows actual on-chain amounts and DEX Screener value estimates, and links Sell to an exact-amount review. Token labels use metadata tickers with exact addresses retained. The review explains minimum output, token approval when needed, gas, slippage, fees and expiry. Missing Alchemy/0x keys show setup required with disabled execution, never fabricated quotes.

The owner has removed Legacy Solana recovery from the product. Do not show its menu item, page or links; old URLs redirect to Portfolio. Preserve stored keys, balances and signed history. Detailed WhatsApp receipts separate quoted estimates from confirmed receipt transfers and gas; include the original ticker and exact token address.

After a newly confirmed WhatsApp pairing, keep the dismissible, accessible iPhone-style preview on the left for 15 seconds: WhatsApp connected successfully, with blue double ticks. Key saving or failed pairing never triggers success. Ticks illustrate feedback, not Meta verification or actual read-receipt status.
